## Explicação da Atividade e Objetivos
 
### 1. Identificar
Localizar erros ocultos (sintaxe, lógica ou execução) em um algoritmo imperfeito.
 
Erros podem ser:
- Erros de sintaxe: código que viola as regras da linguagem
- Erros de lógica: código funciona mas produz resultados incorretos
- Erros de execução: situações que causam falha durante a execução
- Inconsistências estruturais: violações de padrões de design ou semântica HTML
### 2. Corrigir
Refatorar o código e documentar justificativas técnicas para cada alteração.

Processo:
- Reescrever o código limpo e funcional
- Adicionar comentários explicativos em cada correção
- Documentar por que o erro ocorria
- Garantir que a solução é eficiente e escalável
### 3. Avaliar
Auditar a solução final com base em critérios de clareza, eficiência e escalabilidade.

## Principais Conceitos
 
### Tipologia de Erros
- Erros de Entrada (Digitação): Falha humana na entrada de dados
- Erros de Previsão: Falhas na lógica ao processar dados não higienizados
- Filtro de Validação: Verificação de quantidade, tipo e formato de caracteres
### Estratégias de Prevenção
- Simplicidade na Solução: Código claro gera menos espaço para bugs ocultos
- Ação Defensiva: Prever falhas e preparar estados seguros
- Planejamento (Pseudocódigo): Desenhar comportamento antes de codificar
### Técnicas de Sistematização
- Teste de Verificação: Está sendo desenvolvido corretamente?
- Teste de Validação: Atende às necessidades do usuário?
- Teste Estático: Análise de código sem executá-lo
- Teste Top-down: Sistema como um todo
- Teste Bottom-up: Partes pequenas isoladas
---
 
## Ordem de Correção Sugerida
 
1. Bugs de Severidade Alta: quebram funcionalidades principais
2. Erros de Responsividade: afetam múltiplas telas
3. Erros de Semântica: violam padrões e acessibilidade
4. Erros de Estilo: melhorias de código morto
---
 
## Filosofia do Teste de Unidade
 
Um programador de verdade não é aquele que escreve códigos sem erro. É aquele que organiza seu pensamento para prever, testar, corrigir e melhorar seus sistemas antes que os erros causem danos.
